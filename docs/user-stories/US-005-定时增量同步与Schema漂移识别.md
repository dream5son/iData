# US-005 定时增量同步与 Schema 漂移识别

## 用户故事

作为 **实施工程师**，我想要 **为数据源配置基于 Cron 的定期增量元数据同步，并识别 Schema 漂移**，以便 **在企业库结构频繁演进时，数据字典仍能跟上新增表、删减列、类型变更等变化，而不必每次全量手工重建**。

## 优先级 / 依赖

| 项 | 说明 |
| :--- | :--- |
| 优先级 | P1 |
| 依赖 | US-003 连接后自动抽取并持久化元数据 |
| 被依赖 | US-006 元数据快照与版本 |

## 需求说明

为应对 Schema 频繁演进，系统内置基于 Cron 表达式的定期同步调度器，以增量对比读取源库元数据，自动识别漂移。全量首次抽取仍由 US-003 负责；本故事覆盖调度、增量同步与漂移结果。

### 1. 调度配置

对每个 `已就绪` 的数据源，实施工程师可以：

- 启用或关闭定时同步（默认：关闭，避免未评估的生产负载；若产品选择默认开启须在发布说明中明示，验收以「可配置开关」为准）。
- 配置 Cron 表达式（须校验合法；非法表达式拒绝保存）。
- 查看下次计划执行时间（在表达式合法且开关开启时）。

非 `已就绪` 或 `已停用` 的数据源：已配置的调度不得执行；恢复就绪后按当前开关与 Cron 继续。

### 2. 增量同步逻辑

到点或手动「立即同步」时，系统：

1. 确认数据源为 `已就绪`，否则跳过并记录原因。
2. 只读读取源库当前元数据（表/列/索引与物理结构，字段范围与 US-003 一致）。
3. 与数据字典中的 **当前结构** 做增量对比，仅对变更对象更新字典，而非无条件删除重建全部未变对象（实现可内部全量拉取再 diff，但对字典的写入应体现增量：未变化对象保持，变化对象更新）。
4. 产出漂移记录（见下节）。
5. 同步任务状态：`成功` / `部分成功` / `失败` / `跳过`，规则与 US-003 类似：连接配置不被失败破坏；部分对象失败则部分成功。

手动「立即同步」与定时触发共用同一套增量逻辑。

同一数据源同一时刻仅一个同步或全量抽取任务处于执行中；冲突时拒绝立即同步或排队，并明确提示。

### 3. 漂移识别

系统至少识别并记录以下漂移类型：

| 漂移类型 | 含义 |
| :--- | :--- |
| 新增表 | 源库出现字典中不存在的表 |
| 删除表 | 字典中存在但源库已不存在的表 |
| 新增列 | 已有表上新增列 |
| 删减列 | 已有表上缺失原列 |
| 类型变更 | 列的数据类型或精度相对字典发生变化 |
| 可空/主键/默认值变更 | 列约束相对字典发生变化 |
| 索引或分区变更 | 索引、唯一约束、分区/分桶键新增、删除或定义变化 |

每条漂移记录包含：对象定位（Schema、表、列或索引名）、变更类型、变更前值、变更后值（新增则前值为空，删除则后值为空）、检测时间、所属同步任务 ID。

实施工程师可以按数据源查看最近一次及历史同步产生的漂移列表，支持按变更类型筛选。

### 4. 关闭调度

关闭定时同步后，到点不再自动执行；已产生的字典与漂移历史保留。仍允许手动立即同步。

## 验收标准（Given / When / Then）

### AC-001 配置 Cron 并到点执行

- **Given** 数据源为 `已就绪`，实施工程师启用定时同步并保存合法 Cron
- **When** 时钟到达下次计划时间
- **Then** 系统启动一次增量同步任务（可用测试中缩短周期或手动触发时钟的替身验证）

### AC-002 非法 Cron 拒绝

- **Given** 实施工程师输入非法 Cron 字符串
- **When** 保存调度配置
- **Then** 保存失败，字段级错误提示，原调度配置不变

### AC-003 仅同步变更对象

- **Given** 字典已存在，源库仅新增一张表，其余表未变
- **When** 增量同步成功
- **Then** 新表出现在字典中；未变更表的字典内容保持（含未被改写的稳定字段）；漂移列表含「新增表」

### AC-004 识别删减列与类型变更

- **Given** 源库相对字典删除了一列，并将另一列类型变更
- **When** 增量同步成功
- **Then** 漂移记录分别包含删减列与类型变更，且带有前后值；字典与源库当前结构一致

### AC-005 查看漂移列表

- **Given** 一次同步产生了多条漂移
- **When** 实施工程师打开该数据源的漂移/同步结果
- **Then** 能看到对象、变更类型、前后值、时间；可按变更类型筛选

### AC-006 关闭后不再自动跑

- **Given** 定时同步已启用
- **When** 实施工程师关闭调度并保存
- **Then** 之后到点不再自动创建同步任务；手动立即同步仍可用

### AC-007 手动立即同步

- **Given** 数据源已就绪
- **When** 实施工程师点击立即同步
- **Then** 走与定时任务相同的增量对比逻辑，并生成任务与漂移结果

### AC-008 非就绪跳过定时

- **Given** 调度开启但数据源变为 `已停用` 或 `测试失败`
- **When** 到达 Cron 时间
- **Then** 不改写字典，任务为跳过或等价记录，原因可查

### AC-009 无变更

- **Given** 源库结构与字典完全一致
- **When** 同步完成
- **Then** 任务成功，漂移列表为空（或明示「无漂移」）；字典无无意义抖动（不因同步改写未变字段的无关时间戳策略须在实现中保持稳定，验收以结构字段不变为准）

### AC-010 与进行中抽取互斥

- **Given** US-003 抽取任务进行中
- **When** 定时或立即同步被触发
- **Then** 不同时对同一数据源写字典；同步拒绝或排队，并提示原因

## 非功能与约束

- 同步必须只读访问源库。
- Cron 调度应可运维（任务失败可重试策略可配置，但须避免对源库打满连接；并发同步任务数有上限）。
- 增量对比以结构元数据为准，不做行数据抽样对比（行数据不属于本故事）。
- 实现落点：metadata 服务中的调度器与 diff；IDI 前端提供 Cron 配置、立即同步与漂移列表。

## 范围外

- 快照版本号、历史版本浏览与「当前生效版本」（US-006）。
- 语义层对漂移的自动重推断（语义补全故事）。
- 因漂移自动阻断 Agent 查询或发邮件告警的完整通知中心（本故事只需漂移可查看；告警渠道可后续扩展）。
- 同步业务数据或 ETL。
