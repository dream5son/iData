# US-003 连接后自动抽取并持久化元数据

## 用户故事

作为 **实施工程师**，我想要 **在数据源连接就绪后由系统通过 Schema Reflection 自动抽取并持久化元数据**，以便 **无需手工维护数据字典，为查看资产与后续 Code Agent 检索提供与源库一致的结构信息**。

## 优先级 / 依赖

| 项 | 说明 |
| :--- | :--- |
| 优先级 | P0 |
| 依赖 | US-002 深度连接测试（数据源须为 `已就绪`） |
| 被依赖 | US-004 查看数据源元数据；US-005 定时增量同步 |

## 需求说明

连接建立并进入 `已就绪` 后，数据准备模块通过数据库反射机制自动抽取元数据，写入数据字典库。抽取覆盖表、列、索引与物理结构三个核心维度。抽取失败不得破坏已保存的连接配置。

### 1. 触发条件

- 数据源 **首次** 进入 `已就绪` 时，系统自动创建并启动一次全量抽取任务。
- 实施工程师可对已就绪数据源手动触发「重新抽取」（本故事的重新抽取为按当前源库结构刷新字典；增量对比与漂移识别见 US-005）。
- 状态非 `已就绪`（`草稿`、`测试失败`、`已停用`）时不得启动抽取。

### 2. 抽取任务

每次抽取对应一条任务记录，至少包含：

| 字段 | 说明 |
| :--- | :--- |
| 任务 ID | 唯一标识 |
| 数据源 ID | 所属连接 |
| 状态 | `排队中`、`进行中`、`成功`、`部分成功`、`失败` |
| 开始/结束时间 | 可为空直到进入对应阶段 |
| 进度摘要 | 如已处理表数量 / 估计总数（总数不可得则只报已处理数） |
| 错误摘要 | 失败或部分成功时的原因与失败对象列表 |

同一数据源同一时刻只允许一个抽取任务处于 `排队中` 或 `进行中`；重复触发须拒绝或合并提示「已有进行中的抽取」。

### 3. 表级元数据

对每个被抽取的表（含视图表类型若源库可反射），持久化：

| 字段 | 说明 |
| :--- | :--- |
| Schema 名 | 命名空间 / database / dataset，按方言映射 |
| 表名 | 对象名 |
| 表类型 | 如基表、视图、外部表等，以源库反射结果为准 |
| 创建时间 | 源库可提供则记录，否则为空 |
| 存储大小 | 源库可提供则记录，否则为空 |
| 原厂注释 | 源库表注释；无则空，不在本故事中用 LLM 补全 |

### 4. 列级元数据

对每列持久化：

| 字段 | 说明 |
| :--- | :--- |
| 列名 | |
| 数据类型 | 源库类型名 |
| 数据精度 | 长度、精度、小数位等源库可提供的精度信息 |
| Nullable | 是否可空 |
| 主键标识 | 是否属于主键（含复合主键中的成员） |
| 默认值 | 源库默认值表达式或字面量；无则空 |

### 5. 索引与物理结构元数据

持久化：

| 字段 | 说明 |
| :--- | :--- |
| 索引 | 单列与复合索引、索引名、包含列及顺序 |
| 索引类型 | 源库提供的类型（如 BTree、Hash 等），未知则空或「未识别」 |
| 唯一性约束 | 唯一索引 / UNIQUE 约束 |
| 分区 / 分桶键 | 源库可反射则记录分区或分桶键机制；无则空 |

源库不具备某项物理特性时，对应字段为空，抽取任务不得因此整单失败。

### 6. 失败与部分成功

- 连接配置在抽取失败后保持不变，数据源仍可为 `已就绪`。
- 部分表/对象反射失败：已成功对象必须落库；任务状态为 `部分成功`；失败对象记入任务错误列表，实施工程师可重试。
- 连接中断或任务级异常：状态为 `失败`，字典保留 **上一次成功/部分成功** 的数据（首次全失败则字典为空）。
- 抽取过程对源库只读，不得 DDL/DML 写。

## 验收标准（Given / When / Then）

### AC-001 首次就绪自动抽取

- **Given** 数据源刚通过 US-002 四步测试，状态首次变为 `已就绪`
- **When** 就绪状态生效
- **Then** 系统自动创建抽取任务并开始执行，无需实施工程师再点一次「抽取」

### AC-002 三维元数据落库

- **Given** 源库中存在带注释的表、含主键与可空列、以及至少一种索引（或分区，若该库有）
- **When** 抽取任务成功完成
- **Then** 数据字典中可按表级、列级、索引/物理结构三维查询到对应字段；有的字段有值，源库未提供的字段为空

### AC-003 源库无分区不失败

- **Given** 目标库表无分区、无分桶
- **When** 抽取完成
- **Then** 分区/分桶键为空，任务状态为 `成功`（若其余对象均成功），而不是因缺分区失败

### AC-004 部分表失败

- **Given** 抽取过程中部分表反射报错，其余表成功
- **When** 任务结束
- **Then** 成功表已持久化，任务状态为 `部分成功`，错误列表包含失败对象名与原因；实施工程师可再次触发抽取

### AC-005 抽取失败不影响连接

- **Given** 数据源为 `已就绪`
- **When** 抽取因源库超时或权限不足整体失败
- **Then** 连接配置不丢失、状态仍为 `已就绪`，任务状态为 `失败` 并有错误摘要

### AC-006 非就绪不可抽取

- **Given** 数据源状态为 `草稿`、`测试失败` 或 `已停用`
- **When** 实施工程师尝试启动抽取（含 API）
- **Then** 系统拒绝，并说明须先使数据源处于 `已就绪`

### AC-007 手动重新抽取

- **Given** 数据源已就绪且已有字典数据
- **When** 实施工程师触发重新抽取且任务成功
- **Then** 字典反映当前源库结构；进行中不可再开第二个抽取任务

### AC-008 抽取只读

- **Given** 源库仅授予只读账号
- **When** 执行抽取
- **Then** 源库无结构或数据被本任务修改；若账号缺少读 catalog 权限，任务失败或部分成功并列出不可见对象，而非写库

### AC-009 任务可查询

- **Given** 存在进行中或已结束的抽取任务
- **When** 实施工程师查看该数据源的抽取状态
- **Then** 能看到任务状态、时间、进度摘要；失败/部分成功时能看到失败对象列表

## 非功能与约束

- 抽取使用只读连接与 Schema Reflection（SQLAlchemy 2.0 元数据反射为预定实现路径）。
- 大实例（万级表）允许长时间运行，须有进度与可查询任务，避免无反馈的无限等待；具体超时可按数据源配置，但须有上限与失败状态。
- 元数据持久化至数据字典库（PRD：Redis/PostgreSQL 目录存储）；本故事要求可查询、可重入，不绑定唯一存储产品细节。
- 原厂注释按源库原样存储，不做语义改写（语义补全为后续故事）。

## 范围外

- 管理界面中的元数据树、搜索与只读详情展示（US-004）。
- Cron 增量同步、Schema 漂移识别（US-005）。
- 带版本号的元数据快照（US-006）。
- LLM 生成表/列业务说明、推断隐式外键。
- 向量检索、`get_schema_context` 工具与 Agent 上下文加载。
