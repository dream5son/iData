# US-006 元数据快照与版本

## 用户故事

作为 **实施工程师**，我想要 **在元数据同步成功后生成带版本号的快照，并明确当前生效版本**，以便 **后续 Code Agent 检索时使用与生产结构对齐的字典，且必要时可只读回溯历史结构**。

## 优先级 / 依赖

| 项 | 说明 |
| :--- | :--- |
| 优先级 | P1 |
| 依赖 | US-005 定时增量同步与 Schema 漂移识别（快照在成功的增量同步或等价成功刷新后产生；首次 US-003 全量成功亦应生成初始版本，见需求说明） |
| 被依赖 | 无（后续 Schema 检索故事应消费「当前快照」，本批不实现 Agent） |

## 需求说明

PRD 要求增量同步识别漂移后，生成附带版本号的元数据快照，确保 Code Agent 检索使用的元数据与生产环境严格一致。本故事定义快照的产生、当前版本、历史只读浏览及无变更时的升版策略；不实现 Pi 工具与 Agent 会话。

### 1. 快照产生时机

在以下任务 **成功** 完成后生成新快照（状态为 `部分成功` 时：为已成功对象生成快照，快照元数据中标记不完整/部分对象失败，避免被当成完整生产镜像而不加说明）：

- US-003 首次全量抽取成功（形成 **v1** 初始快照，保证未配置定时同步时也有可引用版本）。
- US-005 增量同步成功且相对当前快照 **存在漂移**。

版本号在同一数据源内单调递增（整数序号即可，如 1、2、3），全局可与数据源 ID 组成唯一快照标识。

### 2. 无变更时不升版

US-005 增量同步成功但 **无漂移** 时：

- **不** 创建新版本号；
- 不产生空快照副本；
- 当前生效版本保持不变；
- 可在同步任务上记录「与版本 N 一致，未升版」。

### 3. 当前生效版本

每个数据源有且仅有一个 **当前生效版本**（尚无成功快照时为空）。

- US-004 查看元数据 **默认** 展示当前生效版本对应的结构。
- 新快照产生后，当前生效版本自动指向最新成功快照（部分成功快照是否自动升为当前：仅当实施工程师可在界面看到「部分完整」标记时允许自动指向最新；若部分成功，默认仍自动指向最新，但查看侧必须显示不完整警告，与 US-004 状态提示一致）。

后续 Code Agent / `get_schema_context` **必须** 只读取当前生效快照，不得混用未版本化的临时反射结果。本故事将此作为消费约定写入需求，实现放在后续内核故事。

### 4. 历史版本

实施工程师可以：

- 查看快照列表：版本号、生成时间、来源任务（抽取/同步）、是否当前、是否部分完整、漂移摘要（如变更条数）。
- 选择某一历史版本 **只读浏览** 表/列/索引（交互可复用 US-004 的展示结构）。
- 浏览历史时界面必须标明「只读历史版本 N，非当前生效」，避免与生产当前结构混淆。

本故事不要求从历史版本「一键回滚为当前」（以免 Agent 与生产不一致）；若实现回滚须另开故事。本故事范围仅浏览，不回滚。

### 5. 删除数据源

按 US-001 级联删除时，该数据源的全部快照一并删除。

## 验收标准（Given / When / Then）

### AC-001 首次抽取产生 v1

- **Given** 数据源首次全量抽取成功且此前无快照
- **When** 抽取任务成功结束
- **Then** 存在版本号为 1（或等价首个单调版本）的快照，并被标为当前生效

### AC-002 有漂移的同步升版

- **Given** 当前生效版本为 N，随后一次增量同步成功并检测到至少一条漂移
- **When** 同步任务成功结束
- **Then** 产生版本 N+1 快照，当前生效版本变为 N+1；N 仍可在历史中只读查看

### AC-003 无变更不升版

- **Given** 当前版本为 N，源库与快照 N 结构一致
- **When** 增量同步成功
- **Then** 不出现 N+1；当前仍为 N；任务记录表明未升版

### AC-004 查看默认当前版本

- **Given** 数据源存在多个快照
- **When** 实施工程师打开 US-004 元数据页且未选择历史版本
- **Then** 展示当前生效版本的结构，并可见当前版本号

### AC-005 只读浏览历史

- **Given** 存在版本 N 与 N+1
- **When** 实施工程师选择查看版本 N
- **Then** 展示 N 的表/列/索引；标明为历史只读且非当前；不能通过该浏览修改 N 或 N+1 的内容

### AC-006 快照列表

- **Given** 数据源有多次升版
- **When** 打开版本列表
- **Then** 每条显示版本号、时间、来源、是否当前；有漂移的升版可看到变更条数或可跳转到对应漂移（US-005）

### AC-007 部分成功快照带标记

- **Given** 同步或抽取为 `部分成功` 并生成快照
- **When** 查看该版本或将其作为当前
- **Then** 界面标明该快照不完整，并区别于全量成功快照

### AC-008 消费约定可追溯

- **Given** 文档与数据源详情中的当前版本
- **When** 后续 Agent 检索故事实现前
- **Then** 本故事明确：检索必须绑定当前生效快照 ID/版本号；验收以数据源上可查询「当前快照标识」为准（供后续接口使用）

### AC-009 级联删除

- **Given** 数据源含多个快照
- **When** 按 US-001 确认级联删除数据源
- **Then** 快照均不可再查询

## 非功能与约束

- 快照一旦生成，历史版本内容不可变（append-only / 不可改写），保证审计与回溯一致。
- 快照存储须能支撑 US-004 同等查询；具体引擎（PostgreSQL 目录 + Redis 缓存等）遵循技术栈，本故事不指定表结构。
- 当前快照标识的读取应足够快，供后续检索路径使用（实现阶段可缓存）。

## 范围外

- `get_schema_context`、向量剪枝、Agent Prompt 加载的实现。
- 将历史快照回滚为当前生效版本。
- 语义补全内容纳入快照的合并策略（后续语义故事需规定业务说明是否随结构快照一并版本化）。
- 终端用户查看元数据。
