# IDI 数据源与元数据（US-001～US-006）设计方案

## 背景

`apps/idi` 现为骨架。本批覆盖实施工程师侧：接入数据源、深度连接测试、元数据抽取、浏览、定时增量同步与快照版本。

## 方案对比

| | A. 同进程垂直切片（选定） | B. 拆分 metadata gRPC 微服务 |
| :--- | :--- | :--- |
| 进程 | FastAPI 单体，`idi.datasources` / `idi.metadata` 两域 | 独立 metadata 服务 + gRPC |
| 目录存储 | SQLite（本地可跑） | PostgreSQL + Redis |
| 方言 | Adapter 注册表；真实反射走 SQLAlchemy；本地可用 `__sqlite_path` 桥接 | 全量驱动先行 |
| 前端 | Next.js App Router 调 REST | 同左，多一层 BFF |
| 代价 | 后期拆服务需抽接口 | 首版运维与驱动面过大 |

选定 A。原则：Laziness Protocol（最小可运行面）、Prove It Works（本机可验）、Model the Domain（状态机与 Adapter 注册表先于分支）。

## 核心数据形状

1. **DataSourceStatus** 状态机：`draft` → `test_failed` | `ready`；`ready` ↔ `disabled`；启用后回到需再测通，不直接 `ready`。
2. **ConnectionConfig**：`dialect` + `params: dict`（非每库一实体）。
3. **ConnectionTestReport**：固定四步有序列表，每步 `passed` | `failed` | `skipped`。
4. **CatalogObject**：表 / 列 / 索引三维结构（当前可变目录）。
5. **Job**（抽取或同步）：`queued` | `running` | `succeeded` | `partial` | `failed` | `skipped`；同数据源互斥。
6. **DriftRecord**：按变更类型区分的记录（前后值）。
7. **Snapshot**：不可变版本；无漂移不同升版；每数据源一个 `current_version`。

## 模块地图

```text
apps/idi/backend/src/
  app.py              FastAPI 组合根
  infra/              方言 Adapter、SQLite Store、id/时钟
  datasources/        数据源接入与测连（models / service / api）
  metadata/           抽取、浏览、同步、漂移、快照（models / extract / sync / diff / api）
apps/idi/frontend/    管理台
```

## API 面（REST）

- `GET/POST /api/datasources`，`GET/PATCH/DELETE /api/datasources/{id}`
- `POST /api/datasources/{id}/test`，`POST /api/datasources/test`（保存前）
- `POST /api/datasources/{id}/extract`，`GET .../jobs`
- `GET /api/datasources/{id}/metadata`（表/列/索引、搜索）
- `GET/PUT .../sync-schedule`，`POST .../sync`，`GET .../drifts`
- `GET .../snapshots`，`GET .../snapshots/{version}/metadata`

## 验证策略

后端 pytest 覆盖状态机、凭证不回显、四步测试短路、抽取/漂移/升版。前端 `npm run build`。本地用 `__sqlite_path` 跑通就绪→抽取→浏览→同步→快照。
