# 企业级数据智能体（iData）需求规范与系统架构设计报告

## 总体架构设计与 Pi 内核演进范式

在大型企业的数据治理与商业智能（BI）实践中，传统的自然语言转 SQL（Text-to-SQL）系统长期面临大模型幻觉、复杂多表关联准确率低、隐式业务口径难以对齐以及安全审计防线脆弱等瓶颈。单次 Prompt 提示词生成模式在面对真实企业数据仓库时极其脆弱，无法适应多轮交互、歧义修正以及动态权限管控的严苛要求。企业级数据智能体（iData）通过引入以 Pi 为内核的编码智能体（Code Agent）执行范式，将 NL2SQL 过程从传统的“文本翻译”重构为“具备环境感知、自我修正、动态治理与沙箱执行能力”的智能代码协同模式。

iData 采用三层解耦的整体技术架构，包括数据准备与治理层、内核执行与安全层、展示与交互层。数据准备与治理层负责建立底层数据资产与上层智能体之间的语义映射与权限隔离，提供多源异构数据库连接、元数据抽取与动态更新、语义理解补全、多维行/列权限控制以及角色分析剧本（Playbook）配置功能。内核执行与安全层依托 Pi harness（包含 @mariozechner/pi-agent-core、@mariozechner/pi-coding-agent 与 @mariozechner/pi-ai 等核心模块）作为底座，通过极简的系统 Prompt 约束、基于树状结构的 JSONL 会话持久化、多 LLM 供应商抽象以及定制化数据工具链，实现安全且高效的 SQL 代码迭代生成与沙箱后处理。展示与交互层则负责捕获用户自然语言请求，结合角色 Playbook 进行意图补全与交互式歧义消除，并将最终查询结果交付给数据展示智能体（Presentation Agent）完成图表自适应渲染与业务洞察生成。

### 架构分层

| 架构分层 | 核心模块组件 | 关键技术实现方案 | 交付标准与性能要求 |
| :--- | :--- | :--- | :--- |
| 数据准备与治理层 | 异构数据库连接与元数据引擎 | JDBC/ODBC 驱动池、SQLAlchemy 元数据反射、Redis/PostgreSQL 目录存储 | 支持行业主流数据库，提供秒级连接校验与定时增量元数据同步 |
| 数据准备与治理层 | 语义补全与权限控制引擎 | LLM 语义推断、动态 SQL 谓词注入器、列掩码（CLM）转换器 | 自动生成表列注释与外键关系，实现行级 RLS 与列级脱敏策略注入 |
| 内核执行与安全层 | Pi Code Agent 运行引擎 | Pi AgentSession SDK/RPC、树状 JSONL 会话管理器、模型抽象层 | 子 1,000 Token 极简 Prompt，支持多模型中途切换与上下文自动压缩 |
| 内核执行与安全层 | SQL 安全与沙箱执行环境 | pi-code-tool (Monty Python Sandbox)、静态 AST 解析器 | 拦截 DDL/DML 语句，防止 CVE-2026-12045 多语句注入，只读事务隔离 |

| 展示与交互层 | 数据展示智能体（Presentation Agent） | 动态图表推理引擎（ECharts/G2）、自动化数据洞察文本生成器 | 自动推断最佳图表类型（单值/趋势/对比/透视），输出归因分析文本 |

## 实施工程师视角：数据治理与权限配置规范

### 异构数据库连接管理与元数据自动同步机制

实施工程师作为数据智能体初始化部署的关键角色，必须能够为系统建立稳定、安全的数据连接体系。iData 系统的数据连接模块要求全面兼容企业主流的异构数据库，包括传统关系型数据库（如 Oracle、Microsoft SQL Server、PostgreSQL、MySQL、IBM DB2）、云原生数据仓库与湖仓（如 Snowflake、Google BigQuery、Amazon Redshift、Databricks Lakehouse）以及分布式 OLAP 与实时分析引擎（如 ClickHouse、Apache Doris、StarRocks、TiDB、Greenplum）。实施工程师在配置连接信息（主机地址、端口、数据库名、认证凭证、SSL 加密证书及高级连接参数）后，系统会触发深度连接测试，依次验证网络可达性、凭证合法性、只读事务支持能力以及方言（Dialect）兼容性。

在连接建立后，数据准备系统模块通过数据库反射机制（Schema Reflection）自动抽取元数据并持久化至数据字典库中。元数据抽取覆盖三个核心维度：表级元数据（包含 Schema 名、表名、表类型、创建时间、存储大小及原厂注释）、列级元数据（包含列名、数据类型、数据精度、Nullable 约束、主键标识及默认值）以及索引与物理结构元数据（包含单列/复合索引、索引类型、唯一性约束及分区/分桶键机制）。为了应对企业数据库 Schema 的频繁演进，系统内置基于 Cron 表达式的定期同步调度器，以增量对比机制读取源数据库元数据，自动识别新增表、删减列、类型变更等 Schema 漂移行为，并生成附带版本号的元数据快照，确保 Code Agent 检索时使用的元数据与生产环境严格一致。

### 语义理解引擎与元数据智能补全

企业原始数据库普遍存在字段命名高度缩写、缺乏业务注释以及因历史原因未建立物理外键约束等问题，这构成了 LLM 生成正确 SQL 的主要障碍。iData 数据准备模块集成了基于大语言模型的语义理解补全引擎，旨在自动提升元数据的业务可读性与关联完整性。

语义补全引擎采用“自动推断与人工复核”的双层机制。系统在加载反射元数据后，会自动分析表名、列名及其数据分布特征，结合领域知识库自动生成并补全业务说明。对于缺少物理外键的数据库，引擎会通过列名相似度算法、数据类型匹配度分析、主键/外键数值重合度抽样以及命名惯例规则，自动识别隐式关联关系并进行补全标记，构建出完整的数据集拓扑图谱。实施工程师可以在管理界面上对智能补全的表说明、列说明以及外键关联进行审核、修改与锁定。人工覆盖的语义信息具有最高优先级，后续将在 Context Engineering 阶段被优先加载至 Code Agent 的 Prompt 上下文中。

### 多维细粒度数据权限控制（RBAC/RLS/CLM）

数据安全是企业级数据智能体上线的生命线。实施工程师可以为系统用户创建多层级的角色（Roles），并针对不同角色建立精细到表级、列级与行级别的访问控制策略，保证数据权限在 SQL 编译阶段即被物理收口，杜绝事后过滤带来的数据泄露风险。

| 权限控制维度 | 策略类型 | 策略配置规约与语义表达 | SQL 编译期执行机制 |
| :--- | :--- | :--- | :--- |
| 表级权限 (Table RBAC) | 显式黑白名单 | 针对角色授权可访问的物理表、逻辑视图及 Schema 集合 | 静态 AST 解析器提取 SQL 表引用，非法表引用直接阻断并报错 |
| 列级权限 (Column Masking) | 动态掩码与脱敏 (CLM) | 设定脱敏规则（全掩码、哈希、保留前三后四、区间化处理） | 将 SELECT salary 重写为 SELECT MASK_SALARY(salary, CURRENT_ROLE())[cite: 10, 11] |
| 行级权限 (Row-Level Security) | 直接列匹配 (Direct Match) | 用户属性（如 user.dept_id）与目标表字段直接建立相等/包含关系 | 在 SQL WHERE 子句中自动注入过滤谓词 dept_id = 'D001'[cite: 10, 11] |
| 行级权限 (Row-Level Security) | JOIN 关联匹配 (Join Match) | 当目标表无用户属性列时，通过权限映射表建立多表 JOIN 关系 | 注入 JOIN 映射表：INNER JOIN user_region_map R ON T.region_id = R.region_id[cite: 10] |

行级权限控制要求支持非常灵活的上下文变量绑定。在直接匹配模式下，引擎提取当前登录用户的系统属性并生成谓词；在 JOIN 匹配模式下，当用户请求不包含权限字段的业务表（如订单明细表）时，权限引擎能够根据预定义的权限关联路径，自动改写 SQL 并插入中间权限映射表与关联过滤条件，从根本上杜绝“通过改变提问方式绕过行权限”的安全漏洞。

### 角色化分析剧本（Playbook）配置体系

由于企业终端用户的数据分析素养参差不齐，提交的自然语言需求往往存在表述模糊、缺少时间限定、业务指标定义不清等问题。实施工程师可以为系统中的不同角色配置专属的 Playbook 规则体系，用于对模糊需求进行自动补全与具体化。

Playbook 是由实施工程师维护的领域上下文工程集合，包含以下核心要素：

- **业务术语与指标口径映射**：将模糊的业务词汇绑定到严格的 SQL 计算公式上（例如将“高价值客户”映射为“近 90 天消费金额大于 10,000 元且无退款记录的客户”）。
- **默认时间与维度约束**：当用户提问未指定时间范围时，Playbook 会注入该角色对应的默认时间窗口（如“默认查询本年度 YTD 数据”）。
- **查询安全限制**：为特定角色强制设定 LIMIT 返回行数上限以及禁止跨部门大表全表扫描规则。
- **交互式澄清引导规约**：预定义当关键参数缺失时智能体应当抛出的交互式问答模板。

通过 Playbook 机制，实施工程师成功在自由自然语言输入与企业标准化指标体系之间架起了一座桥梁，极大地提升了最终生成 SQL 的精准度与业务合规性。

## 基于 Pi 内核的 NL2SQL 编码智能体实现

### Pi Agent Core 接入与运行机制

iData 系统选择 Pi（@mariozechner/pi-coding-agent）作为底层 NL2SQL 执行引擎的技术内核。Pi 作为一个极简且高度可扩展的 Agent Harness，摒弃了传统框架中臃肿的硬编码工作流，仅保留核心 Agent Loop、会话树管理、供应商抽象层与插件扩展接口，非常适合嵌入到企业级系统作为高可靠引擎。

系统通过 SDK 方式将 Pi 嵌入后端的 Node.js/TypeScript 服务中。Pi 的 AgentSession 类作为顶层编排器，负责协调 Agent 核心循环、SessionManager 持久化以及 SettingsManager 配置管理。在 NL2SQL 执行过程中，Pi 内核的核心运作机制包括：

- **上下文工程与极简 System Prompt**：Pi 内核自带的 System Prompt 极其简练（通常低于 1,000 Tokens），这确保了有限的上下文窗口能够最大限度用于加载复杂的 Schema 字典、角色 Playbook 以及历史对话轨迹。系统使用 SYSTEM.md 与 AGENTS.md 动态注入企业特定规约。
- **树状会话模型与多分支探索**：Pi 将会话以树状结构（JSONL 格式）持久化存储。当 Code Agent 生成的 SQL 执行报错或校验失败时，Pi 无需清空对话重新开始，而是利用 sm.branch() 或 ctx.fork() 开启一条全新的逻辑分支，仅将错误信息与修正 Prompt 传递给新的分支，在隔离环境下完成 SQL 修复与验证。
- **模型中立性与中途切换**：借助 @mariozechner/pi-ai 统一接口，系统可以根据任务粒度灵活切换模型。例如在需求解析与逻辑推导阶段使用高推理能力的模型，而在 SQL 语法生成与格式化阶段动态切换至低延迟、低成本的模型，从而实现性能与成本的最佳平衡。

### 数据工具链与沙箱执行环境

依托 Pi 的 pi.registerTool 声明式扩展 API，iData 为 Code Agent 量身打造了一套类型安全的封闭数据工具集，将智能体的能力边界从“文本生成”扩展到“编译、校验、改写与沙箱计算”。系统为 Pi Code Agent 注册的核心扩展工具包括：

- **get_schema_context**：接收输入词条，通过语义向量检索与 Schema 剪枝技术（Schema Pruning），仅返回与当前问题强相关的数据表、列定义、数据类型及示例值，避免将无关元数据塞满上下文。
- **validate_sql_ast**：对生成的候选 SQL 进行静态语法树分析（AST Validation），检查表名与列名在数据字典中的真实性，校验方言兼容性，并强制拦截任何试图执行写操作的 SQL 节点。
- **inject_governance_policy**：根据当前请求用户的身份令牌与角色定义，自动在 AST 上重写 SQL，注入行级 RLS 过滤谓词并套用列级脱敏掩码。
- **execute_governed_query**：将安全校验完成的最终 SQL 发送至只读数据库连接池执行，设置严格的查询超时阈值与最大返回行数限制。
- **python_data_transform**：集成 pi-code-tool（基于 @pydantic/monty 沙箱引擎），当用户提出跨表透视、同比环比计算、复杂数据拟合或离群点检测时，Agent 编写 Python 后处理代码并在隔离沙箱中对 SQL 结果集进行二次加工，后处理代码在轻量沙箱中运行，中间变量不进入 LLM 上下文，仅将最终统计结果返回。

### 数据库安全屏障与防注入规约

将 LLM 直接连接至企业生产数据库存在极高的安全隐患。iData 架构在 Agent 与物理数据库之间设立了四层不可越界的安全防护屏障：

1. **数据库连接账号只读隔离**：Agent 专用的数据库连接池统一使用严格受限的只读账号（Read-Only Role），在数据库层彻底剥离 INSERT、UPDATE、DELETE、DROP、ALTER 等写权限，并显式禁止访问操作系统文件与系统过程。
2. **多语句与事务断开攻击防御（CVE-2026-12045）**：针对通过 Prompt 注入攻击试图输出 `COMMIT; DROP TABLE...` 等多语句 Payload 的安全漏洞，系统的 SQL 驱动层强制拦截多语句执行，强行关闭多语句并发开关，并在事务开始时显式执行 `SET TRANSACTION READ ONLY`。
3. **静态 AST 解析与白名单校验**：所有生成的 SQL 在提交数据库前必须通过 AST 静态分析，校验是否包含未授权函数（如系统配置查询函数、外网 HTTP 请求函数），非法节点直接在 Agent 内部拦截并触发安全警告。
4. **资源配额与熔断机制**：为所有查询强制注入 `STATEMENT_TIMEOUT`（如最大 10 秒）与 `MAX_EXECUTION_TIME`，对全表扫描或笛卡尔积查询进行实时熔断，防止生产数据库资源耗尽。

## 终端用户交互流程与数据展示智能体

### 自然语言请求处理与交互式歧义消除

终端用户在 Web 前端界面输入自然语言数据需求，系统按照包含角色匹配、Playbook 展开、歧义判断、沙箱执行与结果呈现的标准化流式链路进行处理。

系统接收到用户请求后，首先提取用户身份 Token 并解析其角色列表，随后检索匹配该角色绑定的 Playbook。系统将用户的原始提问与 Playbook 中的指标定义、时间规则及过滤约束进行融合，完成需求的初步具体化。接下来，Pi Code Agent 评估重构后的需求是否存在多义性。若发现关键维度缺失或指标冲突，Agent 不会盲目猜测 SQL，而是输出带有 `needs_clarification=true` 标记的结构化 JSON，驱动前端界面渲染出交互式澄清组件（如弹出单选框提示用户选择“按合同签订时间统计”还是“按回款时间统计”）。用户点选确认后，澄清选项作为补充上下文追加至 Pi 会话树中，Agent 随即恢复 SQL 生成工作流。在需求明确后，Agent 依次调用工具链完成 Schema 提取、静态 AST 校验、角色 RLS/CLM 权限谓词注入以及物理 SQL 执行。若物理数据库返回错误（如索引失效或临时表空间不足），Pi 会利用树状分支机制在后台发起修复循环，纠正 SQL 后重新尝试，全过程对用户保持透明或以流式日志形式呈现。

### 数据展示智能体（Presentation Agent）与多维渲染

当 Pi Code Agent 成功获取物理数据库的返回数据集后，数据展示智能体（Presentation Agent）接管后续的数据清洗、图表匹配与业务洞察生成工作，确保数据以最直观的方式交付给终端用户。

数据展示智能体结合补全后的用户意图与结果集的数据特征（如数据列数、数据类型、离散度与时间序列属性），自动推断并匹配最佳的视觉呈现样式：

- **单值与 KPI 摘要卡片**：当查询结果为单一标量（如“本月总销售额”）时，渲染为高亮 KPI 卡片，并自动对比历史同期数据输出环比/同比涨跌幅。
- **趋势与序列折线图**：当数据集包含连续的时间维度列（如日、周、月）与数值度量时，自动绘制折线图或面积图，并对数据拐点进行视觉标注。
- **分布与结构柱状图/饼图**：当数据集包含离散分类维度时，根据分类数量自动切换：分类数小于等于 6 时匹配饼图或环形图；分类数大于 6 时匹配纵向或横向柱状图，并自动按数值降序排列。
- **多维透视数据表**：针对包含多个维度与度量的复杂多维数据集，渲染为可交互的数据透视表（Pivot Table），支持用户在前端进行二次筛选、排序、列隐藏及 Excel/CSV 导出。

除了视觉图表渲染外，数据展示智能体还会调用轻量级 LLM 对数据集进行统计学分析与文本解读，生成一段简明的自然语言业务洞察报告。报告内容包含数据极值（Top 1 / Bottom 1 特征）、平均水平、异常波动点以及基于 Playbook 业务逻辑的归因解释，实现“图表展示、明细透视与自然语言解读”的三位一体交付。

## 系统非功能性需求与审计考核标准

### 全链路安全审计与日志追踪体系

为满足企业级数据治理以及合规审计（如 GDPR、数据安全法、等保三级）的要求，iData 系统构建了贯穿“自然语言提问 - 权限注入 - SQL 执行 - 结果导出”的全链路不可篡改日志审计体系。审计日志系统基于高性能消息队列与日志存储引擎构建，每条审计日志条目必须包含以下完整维度：

- **请求上下文元数据**：全局全局唯一 Trace ID、精确时间戳、发起用户 ID、登录 IP 地址、当前激活的角色 ID。
- **意图与 Prompt 轨迹**：用户输入的原始自然语言文本、匹配到的 Playbook ID 及版本号、意图补全后的完整 Prompt。
- **Code Agent 执行轨迹**：Pi AgentSession 的分支路径、生成的前置候选 SQL、AST 静态校验结果、重试修复次数。
- **权限改写与安全审计**：最终提交给数据库的 Governed SQL 文本、被注入的行级 RLS 谓词表达式、被应用的列脱敏掩码策略列表。
- **数据库响应与资源开销**：数据库连接池标识、SQL 执行耗时（毫秒）、返回数据行数、结果集 Hash 校验值（仅保留哈希值用于后续数据泄露追溯，不保存敏感明文）、系统状态码。

## 结论与工程实施路线图

企业级数据智能体（iData）需求规范与架构设计报告，标志着 Text-to-SQL 系统向具备环境感知能力与自愈能力的编码智能体（Code Agent）形态的全面演进。通过以 Pi minimal coding agent 框架作为引擎内核，iData 克服了传统问答系统缺乏复杂控制流与会话隔离的缺陷，利用轻量级系统 Prompt、树状会话持久化与沙箱代码执行能力，实现了高准确率的数据洞察生成。同时，系统将数据治理与安全防御提升到了战略高度，通过数据库只读隔离、防 CVE-2026-12045 攻击事务控制、静态 AST 校验以及动态行/列权限注入，构筑了坚固的企业数据安全防线。

为了确保 iData 系统的高质量交付，建议工程团队按照以下三个阶段稳步推进实施：

1. **第一阶段重点攻坚数据治理与权限安全底座**。团队应集中资源开发异构数据库连接池管理、元数据反射与定时同步服务，并完成基于 RBAC 的表/列/行权限控制引擎与角色 Playbook 配置模块的上线，确保数据资产的可视、可管与可控。
2. **第二阶段全力推进 Pi 内核集成与数据工具链贯通**。工程团队需将 @mariozechner/pi-coding-agent SDK 深入嵌入至后端服务，完成 get_schema_context、validate_sql_ast、inject_governance_policy 等核心工具的编写与注册，并集成基于 pi-code-tool 的 Python 代码沙箱，形成完整的 NL2SQL 生成、校验、改写与执行闭环。
3. **第三阶段聚焦于终端交互体验升级与全链路合规上线**。团队需开发交互式歧义消除组件与数据展示智能体，实现图表自适应匹配与自然语言洞察文本生成，同时全面上线全链路日志审计与越权熔断机制，确保系统在满足企业高并发与严合规要求的前提下顺畅运营。
